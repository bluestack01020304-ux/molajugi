# 몰아주기 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 판매자가 기프티콘을 올리고 구매자가 포인트로 확률 뽑기를 해서, 당첨·꽝·정산까지 실제 폰(Expo Go)에서 동작하는 프로토타입을 만든다.

**Architecture:** 한 저장소에 `app/`(Expo + expo-router 앱)과 `supabase/`(DB 마이그레이션, RLS, Edge Functions)를 둔다. 돈이 움직이는 모든 동작(등록 가격 계산, 뽑기, 정산 확정, 충전, 일일 작업)은 TypeScript Edge Function이 DB 트랜잭션을 직접 열어 처리하고, 앱은 supabase-js로 읽기와 단순 상태 변경만 한다. 규칙 값은 `app_config` 테이블 한 곳, 규칙 로직은 `supabase/functions/_shared/rules.ts` 한 파일에 모은다.

**Tech Stack:** TypeScript, Expo SDK(최신, expo-router), Supabase (Postgres, Auth, Storage, Edge Functions/Deno), postgres.js(`npm:postgres`), supabase-js v2, jest-expo, Deno test, Supabase CLI + Docker Desktop(로컬 스택).

**Spec:** `docs/superpowers/specs/2026-11-07-molajugi-design.md`

## Global Constraints

- 언어는 앱·서버 모두 TypeScript. SQL은 테이블 정의, RLS 정책, 스토리지 정책, pg_cron 예약에만 쓴다. 예외 하나: 회원가입 시 프로필·지갑 행을 만드는 트리거(아래 Task 2). 사업 규칙은 절대 SQL에 넣지 않는다.
- 뽑기 결과와 모든 잔액 변경은 서버(Edge Function)에서만 일어난다. 클라이언트는 `wallets`, `settlements`, `draws`에 쓰기 권한이 없다.
- 규칙 값은 `app_config` 한 곳: `probabilities=[25,50,75]`, `fee_rate=0.10`, `hold_days=3`, `expiry_notice_days=[7,1]`, `min_days_to_list=2`, `topup_amount=10000`.
- 가격 = 액면가 × 확률 ÷ 100, **10원 단위 반올림**. 수수료 = 가격 × 수수료율, 원 단위 반올림. 판매자 몫 = 가격 − 수수료.
- 카테고리 값(DB와 UI 동일): `cafe`(카페), `convenience`(편의점), `chicken_pizza`(치킨·피자), `bakery`(베이커리·디저트), `dining`(외식), `etc`(기타).
- 날짜 기준은 KST. "오늘"은 항상 `todayKst()`로 구한다. `expires_on`은 `date` 타입.
- 바코드 이미지는 비공개 버킷 `gifticons`, 경로 `{seller_id}/{uuid}.jpg`. 서명 URL로만 본다.
- UI 문구는 한국어. 앱 이름 "몰아주기", slug `molajugi`.
- 실결제 없음. 충전은 `topup` 함수가 `topup_amount`를 그냥 더한다.
- 로컬 개발: Supabase CLI 로컬 스택(Docker Desktop 필요). Deno 2.x, Node 20+.
- Edge Function 공통 응답: 성공 `200 {…}`, 실패 `{ "error": "<CODE>" }` + 상태 코드. 코드 목록은 Task 5 Interfaces.

## Review Focus

1. 같은 기프티콘을 두 사람이 동시에 뽑으면 한 명만 당첨되고 나머지는 `LISTING_NOT_ACTIVE`를 받아야 한다. → Task 7 `draw_concurrent_two_buyers_only_one_wins`
2. 잔액이 가격보다 적으면 뽑기가 거절되고 어느 지갑도 변하지 않아야 한다. → Task 7 `draw_insufficient_balance_changes_nothing`
3. 당첨 뒤 판매자가 바코드(이미지·번호)를 더 이상 못 봐야 하고, 제3자는 애초에 못 봐야 한다. → Task 3 `secrets_hidden_from_seller_after_win`, `secrets_hidden_from_third_party`
4. 구매자가 "정상 사용"을 두 번 누르거나 확인 뒤 신고를 눌러도 판매자에게 두 번 적립되거나 상태가 뒤집히면 안 된다. → Task 8 `settle_confirm_twice_credits_once`, `settle_report_after_confirm_rejected`
5. 분쟁 상태인 보류 정산은 3일이 지나도 자동 적립되면 안 된다. → Task 9 `daily_skips_disputed_settlements`

**Files:**

  - `wallet_transactions(id uuid pk default gen_random_uuid(), user_id uuid references profiles, amount int not null, kind text not null check (kind in ('topup','draw','settlement','refund')), ref_id uuid, created_at timestamptz default now())`
  - `listings(id uuid pk default gen_random_uuid(), seller_id uuid references profiles, category text not null check (category in ('cafe','convenience','chicken_pizza','bakery','dining','etc')), brand text not null, product_name text not null, face_value int not null check (face_value > 0), expires_on date not null, probability int not null check (probability in (25,50,75)), price int not null check (price > 0), status text not null default 'active' check (status in ('active','won','withdrawn','expired')), miss_count int not null default 0, created_at timestamptz default now())`
  - `listing_secrets(listing_id uuid pk references listings on delete cascade, image_path text not null, barcode_number text)`
  - `draws(id uuid pk default gen_random_uuid(), listing_id uuid references listings, buyer_id uuid references profiles, amount int not null, result text not null check (result in ('win','miss')), created_at timestamptz default now())`
  - `settlements(id uuid pk default gen_random_uuid(), draw_id uuid unique references draws, seller_id uuid references profiles, buyer_id uuid references profiles, gross int not null, fee int not null, net int not null, status text not null check (status in ('completed','held','confirmed','auto_released','disputed','refunded')), release_at timestamptz, created_at timestamptz default now(), resolved_at timestamptz)`
  - `notifications(id uuid pk default gen_random_uuid(), user_id uuid references profiles, kind text not null, title text not null, body text not null, read boolean not null default false, created_at timestamptz default now())`
  - 인덱스: `listings(status, category)`, `draws(buyer_id)`, `settlements(status, release_at)`, `notifications(user_id, read)`.
  - 트리거 `on_auth_user_created` (허용된 유일한 PL/pgSQL, `security definer`): `auth.users` insert 시 `profiles(id, nickname=split_part(email,'@',1))`과 `wallets(user_id)` insert.

  - `export const sql = postgres(Deno.env.get("DB_URL")!)`
  - `export async function createUser(prefix: string): Promise<{ id: string; jwt: string; client: SupabaseClient }>` — service role `auth.admin.createUser({ email: \`${prefix}-${crypto.randomUUID()}@test.local\`, password: "test1234", email_confirm: true })` 후 `signInWithPassword`로 jwt와 그 유저의 client 반환.
  - `export async function callFn(name: string, jwt: string, body: unknown, headers: Record<string,string> = {}): Promise<{ status: number; json: any }>` — `POST ${SUPABASE_URL}/functions/v1/${name}` with `Authorization: Bearer ${jwt}`.
  - `export async function setBalance(userId: string, balance: number)`
  - `export async function insertListing(sellerId: string, o: Partial<{ face_value: number; probability: 25|50|75; price: number; expires_on: string; status: string; category: string }>): Promise<string>` — 기본값 face 2000, prob 50, price 1000, expires_on = 오늘+30일, 그리고 `listing_secrets(image_path=\`${sellerId}/${id}.jpg\`, barcode_number='1234 5678')` 같이 insert. id 반환.

### Task 3: RLS와 스토리지 정책

**Files:**
- Create: `supabase/migrations/0002_rls.sql`, `supabase/tests/rls.test.ts`

**Interfaces:**
- Produces (정책, 모두 `authenticated` 역할 기준):
  - `profiles`: 본인 select/update(`push_token`, `nickname`만 바뀌는지는 클라이언트 책임).
  - `wallets`, `wallet_transactions`, `draws`, `settlements`, `notifications`: 본인 행 select만. `notifications`는 본인 행 update(`read`)도 허용. 나머지 insert/update/delete 없음(서비스 역할만).
  - `listings`: select는 `status='active'` 또는 `seller_id=auth.uid()` 또는 본인이 당첨한 매물(`exists(select 1 from draws d where d.listing_id=listings.id and d.buyer_id=auth.uid() and d.result='win')`). update는 판매자 본인이 `active → withdrawn`으로 바꾸는 것만(using `seller_id=auth.uid() and status='active'`, with check `status='withdrawn'`). insert 없음(함수가 함).
  - `listing_secrets`: select는 (판매자 본인 and 매물 status<>'won') 또는 당첨자. 그 외 없음.
  - `app_config`: 모든 인증 사용자 select.
  - 스토리지: 비공개 버킷 `gifticons`. `storage.objects` insert는 `bucket_id='gifticons' and (storage.foldername(name))[1] = auth.uid()::text`. select는 같은 조건(판매자 본인) 또는 `exists(select 1 from listing_secrets s join draws d on d.listing_id=s.listing_id where s.image_path=name and d.buyer_id=auth.uid() and d.result='win')`.
  - SQL 도우미 `public.is_winner(listing uuid) returns boolean language sql security definer` 하나는 허용(정책 문구 중복 제거용).
